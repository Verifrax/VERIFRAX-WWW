## 0. Binding doctrine

The VERIFRAX Constitutional Observatory is a derived public projection of the VERIFRAX constitutional perimeter.

It is not a truth source.

It is not constitutional law.

It is not accepted state.

It is not authority issuance.

It is not governed execution.

It is not verification of record.

It is not terminal recognition.

It is a visual, interactive, inspectable projection that may render only to the degree its source chain, projection receipt, ledger entry, attestation, object counts, object roles, and render rights permit.

The Observatory must be constitutionally incapable of pretending.

## 5. Render permissions

The Observatory recognizes exactly three render permissions.

### 5.1 FULL_OBSERVATORY

`FULL_OBSERVATORY` is allowed only when:

* manifest schema is valid
* receipt schema is valid
* attestation schema is valid
* manifest hash matches attestation subject
* receipt hash matches attestation subject
* ledger entry hash matches attestation subject or ledger binding
* repository count is exactly 35
* sovereign chamber count is exactly 9
* ADMISSORIUM is present
* ADMISSORIUM renders only as front gate
* every visible object has a source route
* every sovereign-looking object has sovereign render right
* every host gate has an owner repo
* no blocked warning exists
* browser verification completed without critical failure

### 5.2 SAFE_PROJECTION

`SAFE_PROJECTION` is required when:

* attestation exists but is incomplete
* optional asset hashes are absent
* non-critical object metadata is missing
* WebGL quality is degraded but the object chain remains readable
* a warning exists but does not create active-truth contradiction

SAFE_PROJECTION may show structure, but must visually reduce authority.

### 5.3 BLOCKED_PROJECTION

`BLOCKED_PROJECTION` is required when:

* manifest cannot load
* receipt cannot load
* attestation cannot load
* schema validation fails critically
* repository count is not 35
* chamber count is not 9
* ADMISSORIUM is missing
* ADMISSORIUM appears as sovereign chamber, truth source, or accepted state
* a visible object lacks source-bound render right
* a host gate has no owner repo
* a duplicate active identity appears
* a blocked warning exists
* the render gate cannot determine safety

BLOCKED_PROJECTION must refuse premium geometry.

## 13. Quarantine doctrine

A projection object is quarantined when:

* source route is missing
* duplicate identity exists
* render right is missing
* role is undefined
* host owner is missing
* sovereign role is claimed without chamber class
* ADMISSORIUM claims sovereign status
* enterprise object maps to no real surface
* package object outranks repo truth
* projection object contradicts the manifest, receipt, ledger, or attestation

Quarantined objects must render with:

* no premium geometry
* no sovereign glow
* no authority posture
* containment outline
* warning marker
* inspector-first behavior
* disabled or reduced route action unless safe

Required inspector copy:

```text
QUARANTINED PROJECTION OBJECT

This object exists in projection input but lacks sufficient render authority for full visual status.
```

The system must never make quarantined objects look powerful.

## 20. Failure classes

The Observatory recognizes these failure classes:

### 20.1 Projection drift

Projection output no longer matches manifest, receipt, ledger, or attestation.

Required action: regenerate, downgrade, or block.

### 20.2 Source absence

A visible object lacks a source route.

Required action: quarantine object.

### 20.3 Count mismatch

Repository or chamber count disagrees with attested counts.

Required action: block full render.

### 20.4 Role collapse

A host, repo, package, or implementation object renders as a higher authority than allowed.

Required action: block or quarantine.

### 20.5 ADMISSORIUM misplacement

ADMISSORIUM renders as chamber, truth source, accepted state, or core.

Required action: block.

### 20.6 Overclaim

Visual or textual surface claims stronger machine deference than public objects support.

Required action: fail CI or downgrade copy.
